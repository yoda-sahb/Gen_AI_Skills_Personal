# Book state

Keep instructions, evidence, and progress separate. Use existing files and identifiers rather than creating a competing system.

## Minimum working set

Create only what the current task needs. For a new research-led book, start with a brief and source register. Add claim and chapter records as substantive work develops. Do not create empty administrative files merely to satisfy a template.

| Record | Keep here |
| --- | --- |
| Brief | Book ID, purpose, audience, mode, central question, boundaries, intended length, voice, credit, canonical baseline, current stage, required approvals, file locations |
| Source and claim records | Source access and read status, editions, locators, claims, qualifications, verification, unresolved evidence |
| Chapter and scene ledger | Chapter contribution, evidence, narrative form, scene provenance, repetition checks, drafting and review status |
| Decisions and handoff | Material decisions with reasons, latest accepted and proposed versions, unresolved dependencies, next action |
| Portfolio index, when present | One concise entry per book with status and pointers; no duplicated research dossiers |

Keep each fact in one authoritative location; link or refer to it elsewhere. Combine small records in one file when that is clearer. Split growing records by stable IDs or chapters and retrieve only relevant portions.

## Resume and update

Prefer the latest explicit user instruction over stale project status; record material changes of direction. Never treat an existing draft as newly authorized source material when the user requests a fresh start. Keep archived work available without silently incorporating it.

For substantial work, leave enough durable state for another session to resume: active files, actual reading completed, decisions, unfinished checks, and next action. Record provenance instead of storing sensitive personal details. Do not use internal memory as the sole record.

When comparing across books, retrieve relevant ledger entries by scene, mechanism, or topic. Reuse verified evidence only with its provenance and a fresh relevance check. Do not transfer one book's special rules, approved passages, or attribution into another. If cross-book records are unavailable, state the limit of the repetition check.

Keep workflow changes separate from project decisions. A problem in one draft normally belongs in that book's brief or ledger. Promote a rule into the reusable skill only after the user requests a general change and its value extends beyond that book.
